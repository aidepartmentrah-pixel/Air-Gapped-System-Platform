# UI Design Specification — RAH Offline Installation Platform (Version 1)

## Goal

Design and implement a **modern, professional dark-mode web application** for the **RAH Offline Installation Platform**.

The UI should feel closer to **GitHub**, **Linear**, or **Raycast Dashboard** than to Portainer or Jenkins.

The application is **not a DevOps dashboard**.

It is an **Application Management Platform** whose primary goal is to allow an operator to install, update, verify and manage offline applications.

The UI should always present **Applications** as the central object.

Avoid exposing implementation details such as Docker containers, shell scripts, Docker Compose, Linux commands or databases unless the user explicitly requests technical details.

---

- React
- TypeScript

- TailwindCSS
- shadcn/ui
- Lucide React Icons
- TanStack Router

# Design Principles

The interface should always answer these questions immediately:

- What applications exist?
- Which version is installed?
- Is an update available?
- What action can I perform next?
- Is the system healthy?

Everything else is secondary.

The operator should never need to understand Docker, PostgreSQL, shell scripts or Linux internals to use the application.

The UI should feel like an **Application Center**, not an infrastructure management console.
