## I think this is cleaner than what we did for the Packager

Notice something nice.

The Packager and Platform now become almost symmetric.

|Packaging Engine|Offline Platform|
|---|---|
|Purpose|Purpose|
|Public Operations|Public Operations|
|Internal Workflow|Internal Workflow|
|Request Objects|Request Objects|
|Result Objects|Result Objects|
|CLI Contract|HTTP API Contract|
|State Rules|State Rules|
|Error Contract|Error Contract|
|Safety Rules|Operational Safety Rules|
|Acceptance Criteria|Acceptance Criteria|

I like this much more because both products now follow the same specification pattern. When someone reads your documentation, they'll immediately recognize the structure, and when you later design Engine 3 or another tool, you can reuse the same template. That's a sign that you've found a good documentation architecture rather than inventing a new style for each subsystem.
